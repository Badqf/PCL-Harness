# ADR-002：插件按依赖层并行加载

- 状态：已实现（3.10.6，构建 483 已发布）
- 日期：2026-11-25
- 关联：API v10.4；`docs/更新记录.md` §21.30.74；后续 API 计划见 [API-ROADMAP.md](../API-ROADMAP.md)

## 决定

1. 插件加载按**依赖层**并行：先算出当前所有依赖已满足的插件（同一层），层内最多 4 个同时执行 DLL 加载与 `OnLoad`；上一层全部结束后再算下一层。
2. 依赖关系与顺序语义保持不变：被依赖者先加载；依赖缺失或版本不满足仍然标记失败；循环依赖仍然整批报错。
3. 单个插件的 `OnLoad` 仍限时 **10 秒**（`PluginOnLoadTimeoutMs`），超时只跳过该插件，不影响同层其它插件，也不改变下一层的开始条件。
4. 并发上限用常量 `PluginLoadParallelism = 4`，不暴露给插件；后续若需要可改为设置项。
5. 加载收尾（`FinishRefresh`）仍在 UI 线程统一执行：`PluginsLoaded`、`OnLauncherReady`、标题栏入口重建都只发生一次。

## 理由

- 3.10.4 把加载移到后台后，慢插件不再冻结界面，但串行加载让「多个互不依赖的慢插件」仍然逐个等待，总时长等于各自耗时之和。
- 插件之间真正有顺序要求的场景已经由 `dependencies` 表达，按层并行不会破坏这个语义。
- 4 个并发足以覆盖常见插件数量（本机 14 个、启用的通常 4–6 个），又不会同时创建过多 STA 线程。

## 代价与限制

- 同层插件的 `OnLoad` 日志顺序不再固定，插件不能依赖加载顺序，必须显式声明依赖。
- 超时线程无法强杀：一个卡住的 `OnLoad` 仍会占用一个线程直到自己返回（最多影响该层等待 10 秒）。
- 同一层内是滑动窗口：4 个 worker 持续从队列取任务，某个慢插件不会拖住同层其它插件后面的排队项；但下一层仍要等这一层全部结束。若同层里有一个 10 秒慢插件，已经依赖就绪的下一层插件也要等它超时才继续（后续可改为「依赖一就绪就调度」的 DAG 调度）。

## 如何证伪

- 若同层并行破坏了依赖顺序，应能在日志里看到依赖插件在未完成时被依赖者已经开始 `OnLoad`；用 `dependencies` 链式测试可复现。
- 若超时语义被改动，慢插件（`OnLoad` > 10 秒）应仍被单独跳过，且同层其它插件正常加载。
- 若收尾重复触发，`PluginsLoaded` / `OnLauncherReady` 应各只出现一次；可查日志计数。
