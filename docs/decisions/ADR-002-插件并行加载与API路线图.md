# ADR-002：插件并行加载与下版本 API 计划

- 状态：已采纳（3.10.6）
- 日期：2026-11-25
- 关联：API v10.4；`docs/更新记录.md` §21.30.74

## 决定

1. 插件加载按**依赖层**并行：先算出当前所有依赖已满足的插件（同一层），层内最多 4 个同时执行 DLL 加载与 `OnLoad`；上一层全部结束后再算下一层。
2. 依赖关系与顺序语义保持不变：被依赖者先加载；依赖缺失或版本不满足仍然标记失败；循环依赖仍然整批报错。
3. 单个插件的 `OnLoad` 仍限时 **10 秒**（`PluginOnLoadTimeoutMs`），超时只跳过该插件，不影响同层其它插件，也不改变下一层的开始条件。
4. 并发上限用常量 `PluginLoadParallelism = 4`，不暴露给插件；后续若需要可改为设置项。
5. 加载收尾（`FinishRefresh`）仍在 UI 线程统一执行：`PluginsLoaded`、`OnLauncherReady`、标题栏入口重建都只发生一次。

## 理由

- 3.10.4 把加载移到后台后，慢插件不再冻结界面，但串行加载让「多个互不依赖的慢插件」仍然逐个等待，总时长等于各自耗时之和。
- 插件之间真正有顺序要求的场景已经由 `dependencies` 表达，按层并行不会破坏这个语义。
- 4 个并发足以覆盖常见插件数量（本机 14 个、启用的通常 4–6 个），又不会同时创建过多 STA 线程。

## 代价与限制

- 同层插件的 `OnLoad` 日志顺序不再固定，插件不能依赖加载顺序，必须显式声明依赖。
- 超时线程无法强杀：一个卡住的 `OnLoad` 仍会占用一个线程直到自己返回（最多影响该层等待 10 秒）。
- 同一层内是滑动窗口：4 个 worker 持续从队列取任务，某个慢插件不会拖住同层其它插件后面的排队项；但下一层仍要等这一层全部结束。若同层里有一个 10 秒慢插件，已经依赖就绪的下一层插件也要等它超时才继续（下版本可改为「依赖一就绪就调度」的 DAG 调度）。

## 下一版（3.10.7）范围

3.10.7 确定排入两项下载能力：**断点续传**与**每文件取消**。两者都只改宿主侧行为，不新增状态枚举、不升 `ApiVersionUi`（仍为 10），默认行为与 3.10.6 一致，插件显式开启后才生效。

### 断点续传

- 新增 `PluginDownloadOptions.Resume As Boolean = False`。仅在 `Resume=True` 时启用；启用后即使只有单个 URL 也走顺序下载器（默认 `False` 时单 URL 仍走旧 `LoaderDownload` 路径，行为与 3.10.2 完全一致）。
- 临时文件改为稳定命名（`<目标>.pcldownload`），不再用随机后缀：中断后保留，下次调用同一目标时若临时文件大小小于预期 `Size`，发 `Range: bytes=<已有长度>-` 续传。
- 只接受 `206 Partial Content` 且 `Content-Range` 的起点、总长与本地临时文件一致；服务器返回 `200`（不支持 Range）或总长不一致时，丢弃临时文件从头下载。
- 字节预算按“临时文件已有字节 + 本次新接收字节”计入调用上限；续传不额外消耗尝试次数，但每次 Range 请求算该源的一次尝试。
- SHA-1 仍是最终裁判：校验失败丢弃临时文件并换源，不得把半截文件提交为目标文件。
- 取消/失败时默认保留临时文件（便于下次续传）；若响应缺少 `Content-Range` 或总长不可信则删除。
- 不引入 ETag/Last-Modified sidecar（避免额外文件与兼容负担）；用 `Content-Range` 总长 + 最终 SHA-1 兜底。

### 每文件取消

- 新增 `PluginTaskHandle.CancelFile(RelativePath As String) As Boolean`：线程安全，路径按 `ResolveInstanceRelativePath` 归一化后匹配。
- 命中正在下载的文件时中止当前 HTTP 请求，该条结果置 `Canceled`、消息「已按请求取消该文件」，其余文件继续；不改变整批的 `Cancel()` 语义（整批取消仍立即停止）。
- 返回 `False` 的情况：路径不在本批次、该条已终态、参数非法。未开始的文件被取消时直接标记 `Canceled` 并跳过。
- 被取消文件不消耗剩余尝试次数；字节预算只计已实际接收的字节。
- 整批终态：仍有其它文件成功/失败时按原规则汇总；全部文件都被逐文件取消时，任务以正常完成收尾（不把整批标成 `Canceled`），结果列表里全部为 `Canceled`。

### 验收口径（实现时执行）

- 续传：服务器支持 Range → 中断后重调，服务器日志显示第二次请求 `Range` 起点等于已收字节；最终 SHA-1 正确。服务器忽略 Range（200）→ 自动从头；总长变化 → 从头；SHA-1 不符 → 丢弃换源。
- 每文件取消：三文件批次中取消中间一个 → 该条 `Canceled`、前后两条 `Ok`；整批 `Cancel()` 仍立即停止；`Resume=False` 且单 URL 的旧行为逐字节不变（探针 A–P + G/H/M legacy 用例回归）。
- 预算：续传场景下“已有临时字节 + 新收字节”恰好等于上限时通过，多 1 字节 `TooLarge`。

## 后续版本计划（尚未实现）

以下是当前 API 明确没有、评估后列入后续版本的能力，按优先级排列：

| 优先级 | 能力 | 说明 / 影响 |
| --- | --- | --- |
| P1 | 单请求超时与连接超时 | `DownloadFiles` 现在只有整批取消；坏源只能等宿主网络栈自己超时 |
| P1 | 每文件级取消 | **已排入 3.10.7** |
| P1 | 下载并发数 / 限速控制 | 宿主当前用固定策略；插件无法为大批量下载限制带宽或并发 |
| P2 | 断点续传 | **已排入 3.10.7** |
| P2 | 自定义请求头 / 请求方法 | 目前只支持 GET，不能带鉴权头或 POST |
| P2 | 下载到实例以外的目录 | 路径围栏只允许实例内；需要新的授权模型（例如显式目录授权） |
| P2 | 可选文件选择接口（v9 整合包） | 现在静默安装一律跳过可选文件，只能读 `OptionalCount` |
| P3 | 安装到已有实例 / 整合包升级 | 现在只能新建实例，没有版本更新流程 |
| P3 | 按任务回调 + 并发安装隔离 | 完成事件是全局广播；`ModpackSilentInstall` 是全局标志，两个安装不能并行 |
| P3 | URL 直接安装整合包 / 指定下载源 | 只能装本地文件，镜像沿用全局设置 |
| P3 | Quilt 整合包安装 | Inspect 能识别，安装链路只支持 Forge/NeoForge/Fabric |
| P4 | `PluginModpackInfo.Format` / `Loader` 注释与实际值统一 | 注释写显示名，实际返回小写标识；纯文档修正 |

## 如何证伪（3.10.7 两项）

- 若续传拼接了不同版本的文件，SHA-1 会失败；若把 `200` 当成续传，最终大小或哈希会不符。
- 若逐文件取消影响了整批，其余文件不会继续完成；若取消被忽略，该条会以 `Ok` 结束。
- 若不开启 `Resume` 时行为变化，探针的 legacy 用例（G/H/M）计数与状态会与 3.10.6 不一致。

## 如何证伪（3.10.6 并行加载）

- 若同层并行破坏了依赖顺序，应能在日志里看到依赖插件在未完成时被依赖者已经开始 `OnLoad`；用 `dependencies` 链式测试可复现。
- 若超时语义被改动，慢插件（`OnLoad` > 10 秒）应仍被单独跳过，且同层其它插件正常加载。
- 若收尾重复触发，`PluginsLoaded` / `OnLauncherReady` 应各只出现一次；可查日志计数。
