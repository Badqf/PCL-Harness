# 联机外网地址与「虚拟局域网」方案（计划稿）

> 本文只做方案与可行性评估，不含代码改动。当前版本 v3.1.12。
> 相关代码：`Plain Craft Launcher 2\Pages\PageLink\PageLinkMain.xaml.vb`、`Modules\ModUpnp.vb`、`Modules\ModFirstRun.vb`。

## 一、现状（先对齐事实）

直连模式（`LinkDirectMode`）下：

| 环节 | 现状 |
| --- | --- |
| 监听 | `easytier-core --no-tun --listeners tcp://0.0.0.0:{端口} udp://0.0.0.0:{端口}`，端口从 11010 起找空闲（`PageLinkMain.xaml.vb:641`） |
| 邀请码 | `{局域网IPv4}:{端口}\|{PCL 邀请码}`（`GetDirectInvite()`，`:405`） |
| 外网地址 | 只在 **UPnP 映射成功** 时于完成页显示一行（`DirectPublicEndpoint`，`:471`/`:475`/`:667`） |
| 失败时 | 只有「路由器未开启 UPnP…仅同一局域网可直连」，没有任何公网 IP 信息 |
| 持久化 | 地址只活在内存里，关掉界面就没了，外部工具读不到 |
| 中继节点 | `ServerConfig.json` 默认 `public.easytier.cn:11010` —— **已失效**（DNS 不解析，端口不通），所以现在只剩直连模式可用 |

一句话：**现在能拿到「局域网地址」，拿不到「外网地址」**，而 Radmin / 朋友手动输入 / 其他启动器都需要外网地址。

## 二、方案 A：把外网地址明确写出来（推荐先做）

目标：任何时刻都能一眼看到并复制「本机联机地址」，并落盘给外部软件读取。

### A0. 用户向说明（0.5 小时，纯文档）
在「联机 → 直连模式」页脚加一个「如何让外网连进来？」链接，点开说明三种情况：

1. **路由器支持 UPnP**：点「创建房间」后界面会显示 `外网地址（UPnP 已自动映射）：x.x.x.x:端口`，把这个整串 + 邀请码发给朋友即可。
2. **没有 UPnP**：需要手动做端口映射。查看本机公网 IP 的三种方式：
   - 启动器里：设置 → 联机 → 「检测公网 IP」按钮（本方案 A1 新增）
   - 浏览器打开 <https://ip.sb> 或 <https://ipv4.icanhazip.com>
   - 路由器管理页的「WAN 口 IP」
   然后在路由器里把 `{端口} TCP + UDP` 转发到本机局域网 IP，朋友用 `公网IP:端口|邀请码` 加入。
3. **用 Radmin VPN / 零号等虚拟局域网软件**：先让双方在同一个虚拟网里（Radmin 会分到 `26.x.x.x` 之类地址），这个地址就是「本机在虚拟局域网里的 IP」，直接把它当邀请码里的地址用：`26.x.x.x:{端口}|{邀请码}`。不需要端口映射，也不需要 UPnP。

### A1. 公网 IP 兜底检测（0.5 天）
`Modules\ModUpnp.vb` 里已有 `TryMapPort` / `GetLanIPv4`，新增：

```vb
' 返回本机公网 IPv4；先问路由器（UPnP GetExternalIPAddress），失败再走 HTTP
Public Function TryGetPublicIp(ByRef Ip As String, ByRef Reason As String) As Boolean
```

- 第一优先：UPnP `GetExternalIPAddress`（不产生外网请求，最准）
- 第二优先：`https://api.ipify.org` → `https://ipv4.icanhazip.com` → `https://ip.sb`（15 秒超时、纯文本、失败不阻塞、可在设置里关掉）
- 全程只取 IPv4 文本，不传任何本机信息

### A2. 完成页「地址区」重构（0.5 天）
把现在一行 tip 改成三行可复制地址：

```
本机地址（局域网）  192.168.2.12:12360      [复制]
外网地址            222.69.207.45:12360     [复制]   ← UPnP 成功时有；否则显示「需手动映射」
公网 IP（未映射）   222.69.207.45           [复制]   ← A1 检测结果，供手动映射或 Radmin 参考
```

同时写一份机器可读文件，供外部脚本/软件（含 Radmin 场景的桥接工具）读取：

`%APPDATA%\PCLHarness\LinkAddress.json`

```json
{
  "lan":  { "ip": "192.168.2.12", "port": 12360, "invite": "192.168.2.12:12360|P63DD-..." },
  "wan":  { "ip": "222.69.207.45", "port": 12360, "mapped": true, "via": "upnp" },
  "public_ip": "222.69.207.45",
  "updated": "2026-10-26T23:40:00+08:00"
}
```

关闭房间/退出时删除该文件，避免误导。

### A3. 端口可达性自检（可选，0.5 天）
用 UPnP 查询映射列表确认 `{端口}` 是否存在；或在完成页给一个「自检」按钮，调用 [portchecker.io](https://portchecker.io) 这类公共接口。失败时明确提示「外网访问不了，需要手动映射或改用虚拟局域网」。

### A4. IPv6 直连（暂缓）
双栈用户可免映射直连（`[v6addr]:port`），但国内家宽 v6 稳定性、Windows 防火墙、EasyTier 对 v6 listener 的支持都要单独验，放到 P2 之后。

**A 方案总计：1.5–2 天，零外部依赖、零运营成本、不碰驱动。**

## 三、方案 B：把 Radmin 那套搬进来，可行吗？

### 结论先说
**照搬 Radmin 不可行；但「虚拟局域网」这个目标可以做，用 EasyTier 的 TUN 模式即可，不需要 Radmin。**

理由：

1. **Radmin VPN 是闭源商业软件**（Famatech），没有公开协议、没有 CLI/API、没有可再分发的 SDK；其 EULA 明确禁止反向工程与再分发。技术上无法以库的形式嵌进 PCL，法律上也不允许打包。
2. Radmin 的核心能力是「虚拟网卡 + 自带中继」，这两块我们已有的 EasyTier 全都有——只是当前为了免管理员权限用了 `--no-tun`，把这个开关打开就是同款能力。
3. 我们解压出来的 EasyTier 目录里**已经带了 `wintun.dll` 和 `WinDivert64.sys`**，TUN 模式所需组件是齐的。

### B 方案候选对比

| 方案 | 是否需要管理员 | 是否需要账号/服务端 | 跨公网成功率 | 内嵌成本 | 结论 |
| --- | --- | --- | --- | --- | --- |
| EasyTier TUN（`--no-tun` 去掉） | 是（装 wintun 驱动） | 需要中继或能打洞 | 中（中继依赖自己搭） | 低（已内置） | **推荐 P1** |
| Radmin VPN | 是（装它自己的驱动） | 是（账号+网络） | 高 | 不可行 | 放弃 |
| ZeroTier | 是 | 是（network id，需控制器） | 高 | 中 | 备选 |
| NetBird | 是 | 是（管理端） | 高 | 中高 | 备选 |
| Tailscale | 是 | 是（账号） | 高 | 中 | 不适合开箱 |
| PlayIt.gg 类隧道 | 否 | 是（服务方） | 高（走服务方中转） | 低 | 备选（只做端口转发，不是虚拟局域网） |
| 自建 WireGuard | 是 | 是（自建服务器） | 高 | 高 | 不推荐给普通用户 |

### B 的分阶段计划

**P1. EasyTier TUN「虚拟局域网模式」（2–3 天）**
- 设置 → 联机 增加开关「虚拟局域网模式（需要管理员权限）」；开启时启动器请求提权（UAC），去掉 `--no-tun`，并指定 `--ipv4 10.114.x.y`（按房间号派生，保证同房间不冲突）。
- 界面显示「你的虚拟 IP」和「让朋友输入这个 IP 加入」；MC 侧可以直接「对局域网开放」，也可以让朋友在多人游戏里输入 `10.114.x.y:25565`。
- 风险：UAC 弹窗、杀软对 wintun 驱动的误报、TUN 模式与「游戏进程」的网络命名空间隔离要单独测。

**P2. 可配置中继（1–2 天 + 服务器成本）**
- `ServerConfig.json` 已支持 `Peers`；把「自建中继」做成设置页可填的输入框（如 `tcp://你的服务器:11010`），并给一份自建教程（EasyTier 单文件即可跑中继）。
- 这样即使公共中继下线，用户也能用自己的 VPS 兜底；成本是 1–5 Mbps/房间的带宽。

**P3. 开箱即用中继（运营决策，非纯代码）**
- 需要一台公网服务器 + 域名 + 带宽预算，或接入 PlayIt.gg 这类第三方。是否做取决于你愿不愿意长期养一台中继。

## 四、适不适合做（给结论）

- **A（外网地址可视化 + 落盘 + 说明）**：适合，收益立竿见影，风险几乎为零。你说的「方便 Radmin 之类外部软件获取联机地址」正是 A2 的 `LinkAddress.json`，一次做完，第三方工具直接读文件即可。
- **B（虚拟局域网）**：适合做，但要用 EasyTier TUN，不是搬 Radmin。真正的工作量在「提权 + 驱动 + 中继」，代码量不大，运营和兼容性才是难点。
- **照搬 Radmin**：不适合也不可行，建议放弃这个提法，对外表述为「虚拟局域网模式」。

## 五、建议的落地顺序

1. **今天就能做**：A0 文档 + A2 的地址三行复制（不动网络逻辑）。
2. **紧接着**：A1 公网 IP 检测 + `LinkAddress.json` 落盘。
3. **再评估**：P1 TUN 模式（需要你确认是否接受 UAC 提权）。
4. **最后**：P2 自建中继配置（取决于你有没有 VPS）。

## 已实现的功能
- 完成页新增「地址区」三行：**本机地址 / 外网地址 / 公网 IP**，每行带「复制」按钮。

  ```json
    "wan": { "ip": "222.69.207.45", "port": 12218, "mapped": true },

    "updated": "2026-10-26T23:34:33+08:00"
  }
  ```
- 关闭房间 / 退出联机 / 出错结束时自动删除该文件。
- 设置 → 联机新增两个开关：**创建房间后自动检测公网 IP**（默认关）、**把联机地址写入本机文件**（默认开）。

## 安全措施（可核对）
| 承诺 | 实现方式 |
| --- | --- |
| 不主动联网获取 | 默认只在点「检测公网 IP」时执行；自动检测开关默认关闭 |
| 不上传 | 本项目 `ClsBaseUrl = ""`，`Telemetry()` 第一行即返回，任何事件都不会发出；获取公网 IP 只是读取接口返回的纯文本 |
| 不写日志 | 日志只记录「成功/来源/失败原因」，IP 一律经 `MaskIp()` 打码为 `222.69.*.*`（含 UPnP 映射成功那条） |
| 界面不直接暴露 | 地址区显示打码值，完整地址只能通过「复制」取得 |
| 文件仅本人可读 | 写完即把 ACL 改为「仅当前用户 FullControl」并关闭继承（实测 `Get-Acl` 只剩 `LAPTOP-...\Xiang`） |
| 用完即删 | 关闭房间、退出联机、异常结束时删除 `LinkAddress.json` |

## 无法保证的部分（需要说清楚）
- 联机一旦建立，你的公网 IP 必然暴露给直连的对端——这是 P2P 的物理前提，除非全程走中继。
- 你主动点「复制」后，地址会进剪贴板，可能被剪贴板历史工具记录。
- 同一 Windows 用户下的其他程序理论上仍可读 `LinkAddress.json`（与你同级权限）。
- 截图/录屏请自行打码，程序只能保证「界面上显示的是打码值」。

## 配合 Radmin 等虚拟局域网软件的用法
1. 先让双方在 Radmin VPN 里加入同一个网络，记下本机分到的虚拟 IP（形如 `26.x.x.x`）。
2. 启动器里建房，把邀请码改成 `26.x.x.x:{端口}|{邀请码}` 发给朋友；不需要 UPnP，也不需要端口映射。
3. 若要让外部工具自动拿到地址，读 `LinkAddress.json` 的 `lan.ip` / `lan.port` 即可（Radmin 场景下把 `lan.ip` 换成虚拟 IP 使用）。
