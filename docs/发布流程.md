# 发布流程（务必遵守）

## 一、版本号与提交

1. Plain Craft Launcher 2\Modules\Base\ModBase.vb：改 VersionBaseName（如 "3.7.8"）与两处 VersionCode（正式版/快照版，逐版 +1）。
2. Plain Craft Launcher 2\FormMain.xaml.vb 的 ShowUpdateLog 里，在 If LastVersion < <上一个 VersionCode> 之前插入本版块：

   `b
   If LastVersion < 457 Then 'PCL Harness 3.7.8
       FeatureCount += 1
       FeatureList.Add(New KeyValuePair(Of Integer, String)(1, "优化: ……"))
   End If
   `

3. README.md 的「当前版本」同步。
4. docs\更新记录.md 末尾追加 ## §21.30.xx 标题（x.y.z），含背景 / 改动 / 效果 / 验证 / 坑。
5. PLUGIN-DEV.md 若涉及插件 API，同步改动点（注意该文件是 **LF**，其余多是 CRLF）。

## 二、构建与打包

`
Set-Location 'F:\PCL2-Source'
& .\build.ps1                      # 产物: 'Plain Craft Launcher 2\bin\PCL Harness.exe'
& .\tools\pack-plugin-sdk.ps1 -Version <版本>
`

- pack-plugin-sdk.ps1 默认把 zip 打到 **F:\**（仓库父目录），要手动复制到 F:\PCL2-Release。
- 复制 exe 前先 Get-Process -Name 'PCL Harness' | Stop-Process -Force，否则报文件被占用。

## 三、Git

`
git add -A
git commit -m "feat(scope): summary (vX.Y.Z)"
git tag -a vX.Y.Z -m "PCL Harness X.Y.Z"
git push origin main
git push origin vX.Y.Z
`

## 四、GitHub Release（**每版新建，不要复用**）

> 历史教训：3.7.2–3.7.8 曾因反复 PATCH /releases/<id> 改 	ag_name 复用同一个 Release，导致
> 旧正文/资产被覆盖、published_at 停在首版时间（页面显示「N days ago」），
> 列表里只剩一版。修复方式见 docs\更新记录.md 的相关记录。

正确做法：**每个版本 POST /repos/<owner>/<repo>/releases 新建**，	ag_name 即 X.Y.Z，
body 用 UTF-8 **字节** 提交（[Text.Encoding]::UTF8.GetBytes() + ContentType 'application/json; charset=utf-8'），
否则中文会变成 ?????。

资产只挂在**最新一版**；旧 Release 保留正文、不挂二进制，正文末尾注明「本版本已归档」。

上传：POST https://uploads.github.com/repos/<owner>/<repo>/releases/<新 id>/assets?name=<文件名>
（
ame 用字面文件名，不要 EscapeDataString）。

删除旧资产：DELETE https://api.github.com/repos/<owner>/<repo>/releases/assets/<assetId>（必须写死这条路径，别用拼接的 base；偶发 504 直接重试）。

## 五、发布后自检

- GET /releases/latest 的 	ag_name 是否为本版、published_at 是否为今天、ssets 是否齐全。
- https://ghfast.top/https://github.com/<owner>/<repo>/releases/download/vX.Y.Z/PCL-Harness.exe HEAD 是否 200。
- exe 内 X.Y.Z 字符串计数 ≥ 1、上一版字符串为 0。
- Releases 列表里旧版本条目仍在、正文可读。
