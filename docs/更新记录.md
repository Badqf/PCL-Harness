## 4. 更新检查（确认无官方源）

`Modules\ModSecret.vb` 的 `UpdateCheckByButton` 只读 `PCL_UPDATE_JSON_URL`：

- 未设置 → 只弹提示，不发任何请求；
- 设置为 http(s) → `HttpClient` 取 JSON（10s 超时）；
- 设置为本地路径 → 直接读文件；
- 版本比较用 `CompareVersion(latest, VersionBaseName)`（`ModMinecraft.vb:2431`）。

上游开源版本来就没有官方更新接口（`ModSecret.vb` 里是 `Hint("该版本中不包含更新功能……")` 的占位），因此这里不需要「删除官方源」，只需保证默认不联网——已满足。

> 注意：版本号升到 3.0.0 后，若更新 JSON 里仍是 `2.99.0.0`，不会提示更新（3.0.0 更新）。测试时把 `latest` 写到 `9.9.9.9` 之类。

## 12. 插件页改用原生左侧栏 + 扩展点改展开卡片

**为什么改**：第一版把左侧栏做在页面内部（`MyPageRight.Child` 里的 Grid），靠 `Visibility` 切换分区。结果：`MyCard` 在 `Collapsed` 状态下被加载时，`Init()` 里的虚拟化与高度动画按 0 尺寸算过一次，重新显示后卡片会变灰、内容消失。改成重建式切换后问题消失。

**左侧栏**
- 新增 `Pages\PagePluginLeft.xaml(.vb)`：`Inherits` 原生 `MyPageLeft`，`AnimatedControl="PanItem"`，三项 `MyListItem`（`Type="RadioBox"`、`Height="36"`、`MinPaddingRight="35"`），与 `PageSetupLeft` 完全同构，挂在主窗口 `PanMainLeft` 上。
- `ModMain.vb:400` 新增 `Public FrmPluginLeft As PagePluginLeft`；`FormMain.xaml.vb:1600` 的 `Case PageType.Plugin` 由 `PageChangeAnim(New MyPageLeft, FrmPlugin)` 改为 `PageChangeAnim(FrmPluginLeft, FrmPlugin)`。
- `PagePluginLeft.PageCheck` 直接调 `FrmPlugin.SwitchSection(Tag)`。

**右侧页面**
- `PagePlugin.xaml` 只剩一个宿主：`MyPageRight(PanScroll="PanBack")` → `MyScrollViewer(PanBack)` → `StackPanel(PanContent, Margin 25,25,25,10)`。
- `SwitchSection(Index)`：`PanContent.Children.Clear()` 后按分区重建（管理 / 扩展点 / 开发说明），带 `IsRebuilding` 重入锁，`ScrollToVerticalOffset(0)`。
- 卡片内容必须 `Card.Children.Add(Body)` 且 `Body.Margin = (25,40,25,20)`；用 `BorderChild` 会把内容塞进背景 Border（无内边距、与标题重叠）。

**扩展点改为每插件一张可展开卡片**
- `NewCard($"{DisplayName}  v{Version}")` + `CanSwap = True`、`SwapControl = Body`、`IsSwapped = False`（False 才是展开，MyCard 语义如此），点标题或右上箭头折叠。
- 卡内：一行统计（页面 N · 标题栏入口 M · 设置项 K）+ 每个页面/入口/设置项一行，右侧控件为「打开页面」按钮 / 复选框 / 输入框+保存。

**顺带修掉的重复注册 bug**
- `ModPlugin.SetEnabled` 重新启用插件时，`LoadOne → CollectUi` 会把页面、入口、设置项再追加一遍，标题栏出现两个「示例」。在 `CollectUi` 开头调新增的 `RemoveUi(Info)`（`PluginPages/PluginNavItems/PluginSettings` 各自 `RemoveAll`）修正。

**验证**：三区切换正常、扩展点卡片折叠/展开正常、启用→禁用→启用无重复入口、插件自定义页面仍可从标题栏打开。截图 `screenshots/28-插件页-左侧栏原生.png`、`29-扩展点-每插件展开卡片.png`、`30-扩展点-折叠态.png`、`31-插件开发说明.png`。

  - 文件不存在 / 解析失败 / 缺 `Link` 节点时，抛出的错误信息会直接给出应当放置的完整路径。

- 示例配置：`samples\LinkConfig\ServerConfig.example.json`，`Link` 节点包含 `EasyTierVersion / Downloads / Argument / Peers / MandatoryPeers / PeersBlackList / RandomPeer / DiscoverPeerId / DiscoverPeer`。
  - `Downloads` 支持 `{arch}` 占位（x86_64 / aarch64）；`EasyTierVersion` 用于判断是否需要重新下载。
  - 复制的目标位置：`%AppData%\PCL\ServerConfig.json`（也可以直接放到 exe 同级的 `PCL\ServerConfig.json`，程序会优先用 AppData 那份）。

**EasyTier 模块**
- 官方下载的 zip 里就是 `easytier-core.exe` / `easytier-cli.exe` / `Packet.dll` / `wintun.dll` / `WinDivert64.sys`。解压到 `%AppData%\PCL\EasyTier\` 后重命名为 `联机模块.exe` / `联机模块 CLI.exe` 即可被识别。
- 版本检查读的是注册表 `HKCU\Software\PCLDebug` 的 `LinkEasyTierVersion`（`Sources.Registry`），与 `Setup.ini` 无关；要跳过下载就把该值写成配置里的 `EasyTierVersion`。
- 开源版原解压代码调用的 `FileUtils.ExtractToDirectory` 与 `DirectoryUtils.Copy/EnumerateDirectories` 都被裁掉了（整段只剩注释），已改用 `IO.Compression.ZipFile.ExtractToDirectory` + 手写遍历复制；`System.IO.Compression.FileSystem` 引用本来就在 vbproj 里。

**CLI 调用（关键）**
- `RefreshPeer` 里原本是 `Dim CliResult = ""`，真正的 `StartProcessAndGetOutput(...)` 被注释掉——也就是说即使模块起来了，也永远拿不到节点列表。
- 开源版没有 `StartProcessAndGetOutput`，新增 `RunCliAndGetOutput(FileName, Arguments, TimeoutMilliseconds)`：`ProcessStartInfo` + 异步读取 stdout/stderr + `WaitForExit(timeout)`，超时则 `Kill()` 并抛出明确异常。
- 现在每次刷新都会真正执行 `联机模块 CLI.exe -o json -p 127.0.0.1:{RPCPort} peer`，返回的 JSON 里 `lat_ms` 字段用于判断连接是否建立。

**实测结果（本机）**
- 配置读取：通过，日志 `已从本地加载联机配置`。
- 模块启动：通过，`联机模块.exe` 按 PCL 生成的参数启动，`new listener added listener=tcp://0.0.0.0:12427` 等日志正常。
- CLI 解析：通过，`EasyTier CLI` 加载器以约 60ms 完成，没有出现 `CLI 调用失败`。
- 卡点：公共节点 `public.easytier.cn` 在本机 DNS 返回 NXDomain（`easytier.cn` 可解析但 11010 端口不可达），房间停在「正在连接到节点……」，约 40 秒后失败退出。

**结论**：PCL 侧的联机链路（入口 → 配置 → 下载/解压 → 启动 → CLI 解析）已经全部打通，剩下的只是「能连上的节点」这一外部条件。把可达的中继写进 `ServerConfig.json` 的 `Peers`（或在设置 → 联机 → 自定义节点里填）即可继续。

## 16. 正版登录与 CurseForge：凭据从哪来、怎么配

两个问题都**不是代码缺失**，而是开源版把两把「钥匙」删掉了。登录的 6 步流程、CF 的搜索/文件接口在代码里都是完整的，只是没有 Client ID / API Key。

### 16.1 凭据统一放在 PCL\Secrets.json

支持两种注入方式，环境变量优先：

1. 环境变量：`PCL_MS_CLIENT_ID`、`PCL_CURSEFORGE_API_KEY`
2. 文件 `PCL\Secrets.json`（exe 同级的 PCL 目录下，和 `Setup.ini` 放一起）：
   ```json
   { "MsClientId": "你的客户端 ID", "CurseForgeApiKey": "你的 API Key" }
   ```
   模板：`samples\Secrets.example.json`。改完**重启** PCL Harness 生效。

实现：`Modules\ModSecret.vb` 的 `SecretValue(JsonKey, EnvironmentKey)`，惰性读取并缓存，解析失败只写一条警告，不影响启动。

### 16.2 正版登录（微软账号）

> **前提（2026-10 核对官方文档）**：个人微软账号（@outlook.com / @hotmail.com / @live.com）**不能**直接登录 <https://entra.microsoft.com> 注册应用。这类账号默认被路由到 "Microsoft Services" 租户、其中没有可管理的目录，打开后报 `AADSTS50020` / `AADSTS50058`。
>
> 官方两条硬限制：注册应用所在租户的前提是「An Azure account that has an active subscription」；且「Only paid customers can create a new Workforce tenant…Customers using a free tenant, or a trial subscription won't be able to create additional tenants from the Microsoft Entra admin center」。所以**必须先注册 Azure 账号**——注册流程会自动创建租户，注册者成为该租户的全局管理员，之后才能在 Entra 里注册应用。

步骤（Azure 免费账号 → 注册应用）：

0. 用 InPrivate 窗口打开 <https://azure.microsoft.com/pricing/purchase-options/azure-account> → 「免费开始使用」，用个人微软账号注册 Azure（需手机验证 + 信用卡预授权，试用额度内不扣费）。注册完成后账号下会自动出现一个 Entra 租户，右上角能看到租户名。

1. 打开 <https://entra.microsoft.com> → 「应用」→「应用注册」→「新注册」。
2. 名称随便（如 `PCL Harness Login`）。
3. 「受支持的账户类型」选 **仅此组织目录中的账户** 或 **任何组织目录中的账户和个人 Microsoft 账户** 都可以，但要让个人号能登就必须包含「个人 Microsoft 账户」。
4. 重定向 URI 留空即可（设备代码流不需要）。
5. 注册完成后记下「应用程序(客户端) ID」。
6. 进「身份验证」→ 拉到底部「高级设置」→「允许公共客户端流」选 **是**（`Enable the following mobile and desktop flows` / `Allow public client flows`）。**这一步不做，设备代码流会直接失败。**
7. 不需要生成客户端密码。

然后把客户端 ID 填进 `Secrets.json` 的 `MsClientId`（或环境变量 `PCL_MS_CLIENT_ID`），重启 → 启动页「正版」→「登录」，会出现设备代码弹窗（一串代码 + 一个网址），浏览器打开输入即可。

- 未配置时的表现：会直接弹红字提示「尚未配置微软登录的客户端 ID…」，而不是抛微软返回的 400 原始 JSON（`EnsureOAuthClientId()`，在 `MsLoginStep1New` / `MsLoginStep1Refresh` 开头调用）。
- 刷新登录走 `login.live.com/oauth20_token.srf`，与首次登录的 v2.0 设备代码端点共用同一个 Client ID，这是原版行为，保持不变。

### 16.5 没有信用卡 / 没有学校账号时，正版登录还有哪些路

**结论先说：没有「用个人微软账号 + 不绑卡」就能自建租户的官方路径。** 租户是注册应用的前提，而租户的前提是 Azure 账号（活跃订阅），Azure 免费账号的注册又要手机 + 信用卡预授权。所以下面几条是替代，不是绕开：

| 路径 | 要不要卡 | 能做什么 | 代价 / 限制 |
| --- | --- | --- | --- |
| **A. 加入别人的租户（guest）** | 不要 | 在对方租户里注册自己的应用，拿到 Client ID，正版登录完整可用 | 需要认识一个有租户的人（Azure / M365 都行）；对方要给你 `Application Developer` 角色，或在「用户设置」里允许用户注册应用；离开租户即失效 |
| **B. 外置登录（LittleSkin / Authlib-Injector）** | 不要 | 用皮肤站账号登录，进支持外置登录的服务器；皮肤、披风正常 | 不是 Mojang 正版身份，进不了只认正版服的服务器；**必须先装一个游戏版本才有入口**（见下） |
| **C. 离线登录** | 不要 | 单机、局域网、离线服 | 无正版身份，部分服务器拒绝 |
| **D. 借用公开 Client ID（灰色）** | 不要 | 技术上能跑通设备代码流 | **不推荐**：违反 Microsoft 使用条款，随时被吊销；令牌经过别人的应用，账号安全不受控。仓库不内置、不提供任何具体 ID |

**已验证的事实（2026-10，本机实测）**
- LittleSkin 的 Yggdrasil 端点 `https://littleskin.cn/api/yggdrasil` 返回 200，`meta.serverName = LittleSkin`，`implementationName = Yggdrasil Connect 0.0.8`，`signaturePublickey` 800 字符 —— 协议层可用。
- `authlib-injector` 最新版 **1.2.8**，主源 `https://authlib-injector.yushi.moe/artifact/latest.json` 与 BMCLAPI 镜像 `https://bmclapi2.bangbang93.com/mirrors/authlib-injector/artifact/latest.json` 都返回 200，PCL 里两条都会走（`ModMinecraft.vb:2105` 起，含镜像替换）。

**外置登录在 PCL 里的入口（为什么很多人找不到）**
- 登录类型是 `McLoginType.Auth`（`PageLaunchLeft.xaml.vb:357-362`），标签取 `CacheAuthServerName` / 版本级 `VersionServerAuthName`，为空时显示「第三方登录」。
- 它绑定在**版本**上：没选版本时点它只会提示「请先下载游戏，再设置第三方登录！」（`FormMain.xaml.vb:1005`）。所以顺序是 **先装游戏 → 再配置 authlib 服务器**。
- 两种配置方式：① 在「版本设置 → 设置 → 服务器选项」里填 authlib 服务器地址（PCL 自带「覆盖为 LittleSkin 登录」按钮，`PageInstanceSetup.xaml.vb:378`）；② 点 `authlib-injector:yggdrasil-server:<url>` 协议链接，PCL 会自动接管（`FormMain.xaml.vb:967-1022`）。
- 启动时会把 `authlib-injector.jar` 作为 `-javaagent` 注入，并传 `-Dauthlibinjector.yggdrasil.prefetched=<base64(服务器元数据)>`（`ModLaunch.vb:1287-1291`）。

**不建议**：用虚拟信用卡凑 Azure 验证去过免费额度。涉及资金与合规风险，而且订阅到期/被风控会连累租户。

**如果以后拿到 Client ID**：直接填 `PCL\Secrets.json` 的 `MsClientId`（或环境变量 `PCL_MS_CLIENT_ID`）即可，代码侧不需要再改。

## 17. 示例插件瘦身 + 插件页分区切换动效

**示例插件默认不再注册页面和标题栏入口**（`samples\DemoPlugin\DemoPlugin.vb`）
- 顶部新增条件编译开关 `#Const DemoPageEnabled = False`：`GetPages` / `GetNavItems` 在关闭时返回空集合，`GetSettings` 只保留「加载时弹出提示」。想恢复整套演示，把 `False` 改成 `True` 重新编译即可。

**插件页左栏切换加回入场动效**

## 17. 插件 API v3：事件钩子、更多设置类型、宿主增强

**为什么要做**：v2 只能注册「页面 / 入口 / 设置项」，插件拿到控制权只有 `OnLoad` 一次；想在页面切换、游戏启动前后做点事就没办法。

**`IPclPluginEvents`（新接口，可选实现）**
- `OnLauncherReady()`：启动器初始化完成、所有插件加载后调一次（`FormMain` 初始化线程末尾 `RunInUi` 里 `ModPlugin.RaiseLauncherReady()`）。
- `OnPageChanged(Page, SubType)`：主页面切换后触发（`FormMain.PageChange` 与 `PageChangeActual` 两处调用 `RaisePageChanged`）。
- `OnGameLaunching(Info)`：构建启动参数时触发，可向 `Info.ExtraJvmArgs` / `Info.ExtraGameArgs` 追加参数（`ModLaunch.McLaunchArgumentMain` 内追加，`InstanceName` / `InstanceFolder` / `PlayerName` 一并带上）。
- `OnGameLaunched(Info)`：进程启动后触发，`Info.ProcessId` 可用（`McLaunchRun` 里拿到的 PID 回填）。
- 所有回调都包在 try/catch 里，插件异常只记日志，不打断启动器；`PluginEventHandlers` 列表由 `CollectUi` 收集，`RemoveUi` 一并移除，避免重载重复触发。

**设置类型扩展**
- `PluginSettingType` 增加 `Number`（`MinValue` / `MaxValue`，越界夹紧）与 `Choice`（`Options As String()`）。
- 插件页的 `BuildSettingControl` 相应渲染为「输入框 + 范围提示 + 保存」与「`MyComboBox` 下拉，选中即写入」。
- 写入仍走 `ModPlugin.SetSetting`，落 `PCL\Plugins\plugins.settings.json`。

**`PluginHost` 增强**
- 新增 `InstanceName` / `InstanceFolder` / `PlayerName`（当前选中的版本与玩家）。
- 新增 `Navigate(Page As Integer)`（切主页面，参数为 `FormMain.PageType` 数值）。
- 新增 `RunInUi(Action)` 与 `RunLater(Milliseconds, Action)`，省得插件自己写 Dispatcher。

**示例插件同步升级到 v1.3.0**：实现 `IPclPluginEvents`（就绪时打日志、页面切换时记一行、启动前后各记一行），设置项变成三类共 3 个（勾选 / 数字 1~5 / 下拉主题），可直接当模板抄。

**文档**：`PLUGIN-DEV.md` 标题升到 API v3，文末追加「API v3 追加内容」（事件接口、设置类型表、`Host` 成员表、版本对照）。

## 20. 联机直连模式（P2P-only）

### 20.1 需求与结论

用户希望联机"只利用 P2P 直连，直接本地化"。结论：**可行，但只在特定网络条件下成立**。

- 可行：同局域网直连；房主公网可达（有公网 IP / 已做端口映射 / 路由器支持 UPnP）。
- 不可行：任意 NAT 后两端零服务器互通。NAT 穿透必须有第三方交换地址（STUN、发现节点、信令服务器皆属此类），这是协议层限制，无法靠改代码消除。
- 另一个与服务器无关的硬依赖：EasyTier 需要 TUN 虚拟网卡（管理员权限 + wintun 驱动）。本机实测未装驱动时 `-i` 直接报 `Failed to create adapter`；`--no-tun` 时无可用本地地址，连接报 `10049 AddrNotAvailable`（smoltcp 亦未成功）。

### 20.2 实现内容

- 新增 `Modules\ModUpnp.vb`：极简 UPnP IGD 客户端（SSDP 发现 → 取设备描述 → `AddPortMapping` TCP/UDP → `GetExternalIPAddress`）。本机路由器（Huawei-ATP-IGD，192.168.2.1）可被 SSDP 发现。
- `Pages\PageSetup\PageSetupLink.xaml` 新增「直连模式」卡片与 `LinkDirectMode` 开关。
- `Pages\PageLink\PageLinkMain.xaml.vb`：
  - `IsDirectMode`、`DirectPeerAddress`、`DirectListenPort`、`DirectPublicEndpoint` 四个状态；
  - 直连模式下完全跳过 `GetTargetPeers()`（不再访问 `uptime.easytier.cn`、`easytier.meloong.com`、发现节点与中继）；
  - 启动参数追加 `--listeners tcp://0.0.0.0:{DirectListenPort} udp://0.0.0.0:{DirectListenPort}`、`--p2p-only true`、`--stun-servers ""`（禁用内置 STUN）；
  - 房主启动后尝试 UPnP 映射该端口，成功则邀请里附带外网地址；
  - 邀请格式变为 `房主IP:端口|邀请码`，`JoinInternal` 会先剥离【】再按 `|` 拆出地址与邀请码；
  - 直连房主不再等任何节点，启动 1.2s 后直接进入完成页；
  - `ProcessStart` 增加管理员检查，无权限时用 `Verb = "runas"` 提权启动联机模块（此时无法重定向输出，不影响功能）。
- `ModUpnp.vb` 需加入 `.vbproj` 的 `<Compile Include>`，否则报 `BC30451 未声明 ModUpnp`。

### 20.3 使用方法与限制

1. 设置 → 联机 → 勾选「只使用 P2P 直连」。
2. 房主：联机 → 创建房间 → 输入 MC 对局域网开放的端口；页面显示 `IP:端口|邀请码`，并自动复制。
3. 加入者：联机 → 加入 → 粘贴整串。
4. 首次启动联机模块会弹 UAC（创建虚拟网卡需要管理员），选「是」。

限制：同一局域网最稳；公网需要 UPnP 或手动端口映射；若双方都在对称 NAT 后且路由器无 UPnP，则仍然连不上——这种情况必须有中继或公网端点，这是无法绕过的。

### 22 联机直连「建房 1 秒后网络连接已断开」的修复

### 21.16 首次启动指引窗口：按钮点了没反应（v3.1.6）

### 21.25 迁移引导：跳过后的二次机会（v3.1.15）

现象：首次启动的「欢迎使用 PCL Harness」迁移引导里点了「跳过」后，标记文件写下，之后再也不弹；用户其实只是手滑或当时没看清，就永久失去了迁移旧 PCL 设置/插件的机会。

规则（只给一次机会，且以「有没有真的动过设置」为准）：

1. 首次启动点「跳过」→ 写 `PCLHarness\FirstRun.done`（首次引导已走完）和 `PCLHarness\FirstRun.skip`（内容 `skipped=时间` + `touched=0`），日志：「首次启动：已跳过，下次启动时若未改动设置会再提示一次」。
2. 下次启动 → `FormMain` 的判断从「仅首次启动」改为 `ModFirstRun.NeedWizard()`（`IsFirstRun() OrElse File.Exists(PathSkip)`）；`ShouldShowAgain()` 读取 skip 文件：
   - `touched=0` → 再弹一次，窗口文案改为「上次你点了『跳过』……这次关掉后就不会再提示了」，跳过按钮文字变成「不再提示」；
   - `touched=1` → 说明用户已经在正常配置启动器，删除 skip 文件、不再提示，日志：「上次跳过后已经改过设置，不再重复提示迁移」。
3. 二次机会无论迁移还是跳过，都先 `MarkDone()` 再 `ClearSkip()`——只给一次，不会出现第三次。
4. 「动过设置」的判定挂在唯一入口 `Pages\PageSetup\SettingService.vb` 的 `SaveSetting` 上（设置页控件值变化都会走这里，且被 `AniControlEnabled` 挡掉了程序化刷新），调用 `ModFirstRun.NotifySettingsTouched()` 把 skip 文件改写为 `touched=1`（保留原 `skipped=` 时间），日志：「用户已修改设置，之后不再提示数据迁移」。
5. 迁移成功或勾选项为空（等价跳过但已经在引导里操作过）也会走对应的清理逻辑。

实测（`F:\PCL2-Release`，日志 `F:\PCL2-Release\PCLHarness\Log1.txt`）：

## §21.30.13 虚拟局域网状态可观测性（3.4.1）

- **完成页只显示该连的地址**：`RefreshAddressPanel()` 增加 TUN 分支——标签文案改为「虚拟地址」、内容 `10.114.114.1:{端口}`；「外网地址」「公网 IP」「检测公网 IP」整组收起（`LabAddrWanLabel` / `LabAddrPublicLabel` / `PanAddrDetect`），避免朋友照着 192.168/222.69 的地址去连。复制按钮提示按模式区分：「已复制虚拟地址」/「已复制本机地址」。
- **状态条三态**（`UpdateTunStatus`，每 3 次 `Update()` 探测一次，约 3 秒）：
  - 房主 0 人：蓝「等待朋友加入 · 虚拟地址 10.114.114.1:{端口}」；
  - 房主有人但游戏端口没开：黄「已连上 N 位朋友，但游戏端口 {端口} 还没开放：进游戏后点「对局域网开放」即可」；
  - 房主有人且端口已开：蓝「已连上 N 位朋友 · P2P 直连 · 游戏端口 {端口} 已开放」（有中继时写「N 位走中继」）；
  - 加入者：无对端「已进入虚拟局域网，正在等待房主出现……」；端口不通「已进入虚拟局域网，但房主的游戏端口 {端口} 还没开放（等房主进游戏开房间）」；通了「已连上房主 10.114.114.1:{端口} · 直连 · N ms」。
- **连接质量**：`BtnFinishPing.ToolTip` 显示「P2P 直连 / 经中继 · RTT x.x ms · NAT 本机 / 对端」，双方 NAT 都是 Unknown 时省略 NAT 段（直连模式不带 STUN，Unknown 属正常）。TUN 且没有对端时，底部 ping 区显示「等待连接」而不是原来的「连接优化中」。
- **探测实现**：`IsLocalPortListening(Port)` 用 `IPGlobalProperties.GetIPGlobalProperties().GetActiveTcpListeners()` 判断房主本机是否有人在监听游戏端口（异常时返回 True，宁可漏报也不误报）；`CanReachTcp(Host, Port, 700)` 用 `TcpClient.ConnectAsync().Wait(700)` 判断加入者能否摸到房主端口。
- **实测方法（单机即可复现）**：房主用真实启动器开 TUN 房间；另起一个非提权 EasyTier 节点冒充朋友，参数 `--no-tun --network-name=<日志里的网络名> --network-secret=<密钥> -p tcp://<房主局域网IP>:<监听端口> --hostname=Client-TEST --private-mode true`。三个状态依次验证通过：0 人 → 蓝色「等待朋友加入」；1 人 + 端口未监听 → 黄色「游戏端口 25565 还没开放」；用后台 job 监听 25565 后数秒 → 蓝色「已连上 1 位朋友 · P2P 直连 · 游戏端口 25565 已开放」。`easytier-cli -p 127.0.0.1:<rpc端口> peer` 可看到伪节点 `Client-TEST p2p 0.2ms NAT PortRestricted`。
- **坑**：① 网络名/密钥必须从启动器日志（`正在启动 EasyTier：…--network-name=…--network-secret=…`）或邀请码解析，盲目按邀请码前两段猜会得到错误网络名（本次实际是 `P63DD-CXJJB` 而不是 `P63DD-CXJB`），握手会被踢、日志里表现为 `new peer added` → `peer connection removed` 反复抖动；② `Start-Job` 里开的 TcpListener 会随着那次 pwsh 调用结束而消失，要用后台 job 才能维持监听；③ RPC 端口是随机的（本次 12870），不是监听端口，也不是上一局的端口。

## §21.30.14 首次启动改为自动迁移（3.4.2）

- **问题**：首次启动不是自动迁移旧 PCL 的数据，而是弹一个窗口让用户逐项勾选、再点「迁移并进入」；不勾或点了跳过就什么都不搬，和「装好就能接着用」的预期不符。
- **改法**：
  - 新增 `ModFirstRun.AutoMigrateOnStartup()`，在 `Application.xaml.vb` 里紧跟 `MigrateRegistry()` 与日志初始化之后调用——此时设置还没被读取，**迁移过来的 `Setup.ini` 本次启动就生效**（窗口大小、主题、下载源等立刻按老配置走），不再是「下次启动生效」。
  - 迁移一律自动、全量（只搬旧目录里真实存在的项），旧文件不删除也不修改，只往新目录补缺失内容（文件夹递归合并、文件按 `Overwrite` 覆盖）。
  - 主窗口起来后由 `ShowWizardIfNeeded()` 只弹一次**结果页**：标题「已自动迁移旧 PCL 的数据」，复选框全部置灰、只剩「打开旧目录」和「完成」，文案写明「旧数据没有被删除或修改；迁移来的设置本次启动即生效」。
  - 旧目录里没有任何可迁移数据时不弹任何窗口，只写标记（独立目录的说明交给介绍页）。
  - 老版本遗留的 `FirstRun.skip`（上次点过跳过、之后没改过设置）仍走一次**手动**确认，避免覆盖用户已经在用的新配置；`PCL_FIRSTRUN_AUTORUN=1` 仍可静默（不弹结果页）。
- **验证**（`F:\PCL2-FirstRunTest2`，旧目录只放 `PCL\Setup.ini`）：
  - 旧文件写 `WindowWidth:1500` / `WindowHeight:900`，启动后主窗口实测 1875×1125 物理像素（= 1500×900 @125%），说明迁移在设置读取前完成、本次生效；
  - 日志 `旧 PCL 数据迁移完成：复制 4，跳过 0，失败 0` → `首次启动：已自动迁移旧 PCL 数据（复制 4，跳过 0，失败 0），旧数据未删除也未修改`；
  - `PCLHarness\Setup.ini` 里同时保留了迁移来的键与程序自己写入的 `LaunchFolderSelect`，旧目录文件原样保留；点「完成」后写出 `FirstRun.done`，再次启动不再出现任何迁移窗口。
- **坑**：
  - PCL 的 `Setup.ini` 是 `键:值` 格式（冒号），写成 `键=值` 会被解析成空表，随后程序保存设置时还会把文件重写成自己认识的键——测试数据格式错了会误判成「迁移没生效」。
  - 测试时若上一个测试实例没关，单例互斥体会让新实例直接退出，表现为「启动后什么都没发生」。
  - 早期测试用假的 `Custom.xaml`（内容 `<x/>`）会触发「刷新背景图片失败」错误框，属于测试数据问题，不是回归。

## §21.30.16 更新弹窗一定可见（3.4.4）

- **用户反馈**：更新到新版本后启动，还是没看到「更新了什么」的弹窗；另外希望检测更新后能提示「当前为最新版 x.x.x」。
- **根因一（看不到弹窗）**：3.4.3 仍用 `SystemHighestBetaVersionReg` 当门槛（`If HighestVersionCode >= VersionCode Then Return`）。这个值存在注册表里、全局共享，只要本机先前跑过同版本或更高版本的构建，它就已经被抬高，真正的更新反而不弹。改为：只要 `SystemLastVersionReg` 与当前 `VersionCode` 不同（即版本号真的变了），就取 `ShowUpdateLog(LastVersionCode)`，按「旧版本 → 当前版本」这段列条目；不再读最高版本号，静默替换标记 `Applied.txt` 只保留「顺手删掉」的作用。
- **根因二（弹窗被盖住）**：更新弹窗在 `FormMain` 构造期弹出，而启动 900ms 后「Startup Dialogs」线程会弹介绍页——`ModIntro` 是独立的模态窗口（`Owner = FrmMain`，`ShowDialog`），会盖在主窗口的 `MyMsgBox` 之上，于是用户只看到介绍页。改为：`UpgradeSub` 只把旧版本号记进 `PendingUpdateLogVersion`，等 "Startup Dialogs" 线程里 `ModFirstRun.ShowWizardIfNeeded()` 结束后再由 `ShowPendingUpdateLog()` 弹出（`MyMsgBox` 双按钮会阻塞等待，天然把介绍页排到后面）；这一轮弹过更新日志就不再弹介绍页，留到下次启动。
- **当前为最新版提示**：`StartAutoUpdateCheck` 在判断「不比新」时先 `Hint("当前为最新版 " & VersionBaseName)`，紧接着「正在检测更新……」出现，形成「检测中 → 已是最新」的连续反馈。
- **版本**：3.4.4 / 426；changelog 两条（修复弹窗被跳过、新增最新版提示）。
- **验证**（`F:\PCL2-UpdateTest`）：427 测试构建（仅本地验证用，未发布）从 426 启动，日志 `版本号 426 → 427，稍后展示更新日志` → 1.2 秒后 `普通弹窗：PCL Harness 已更新至 3.4.4`，截图 `%TEMP%\v434-3-deferred.png` 同时看到弹窗与左下角「正在检测更新……」+「当前为最新版 3.4.4」两条 Hint，介绍页没有再冒出来盖住弹窗。
- **坑**：`ShowUpdateLog` 是实例方法、`PendingUpdateLogVersion`/`ShowPendingUpdateLog` 是 `Shared` 的，跨成员访问要写 `FrmMain.ShowUpdateLog(...)`；测试「待展示」路径必须让 `VersionCode` 与注册表里的 `SystemLastVersionReg` 不同，验证完记得把临时版本号改回去再打包。

## §21.30.17 联机诊断（3.4.5）

- **用户需求**：TUN 联机失败时无法判断卡在哪一步（网卡没起来、端口没通、还是打洞失败），希望联机页能给一份可直接发出来的诊断结果。

## §21.30.18 联机端口选择修复（3.4.6）

- **用户反馈**：在陌生环境（另一台电脑）里创建房间时，启动器直接弹「联机出错：联机模块已崩溃 / 监听端口失败」，日志是 `failed to listen on tcp://0.0.0.0:12270 ... os error 10048（通常每个套接字地址只允许使用一次）`。
- **根因**：端口不是「空着」就一定能绑。`ModNet.FindFreePorts`（`Modules\Base\ModNet.vb:1885`）只比对 `GetUsedPorts()` 的快照（`GetActiveTcpListeners` + `GetActiveUdpListeners` + `GetActiveTcpConnections`），查不到「被系统预留、但没有任何程序在监听」的端口；装了 Hyper-V、WSL、Docker 的电脑会预留成段端口（`netsh int ipv4 show excludedportrange protocol=tcp` 能看到），EasyTier 一绑就 10048 退出。原来的起点是 `12000 + RandomInteger(0,1000)`，正好容易落进这些预留段。
- **修复**（`Pages\PageLink\PageLinkMain.xaml.vb`）：
  - `CanBindPort(Port)`：真的去 `TcpListener(IPAddress.Any, Port).Start()/Stop()` 再 `Using New UdpClient(Port)`，两条都成功才算可用，能挡住预留段与占用。
  - `PickBindablePorts(Count, Excludes)`：起点改成 `RandomInteger(20000, 30000)`，连续段里每个端口都要「不在 `GetUsedPorts()` 且 `CanBindPort`」，最多试探 19000 个起点，全失败才退回上游的 `FindFreePorts`。
  - 所有端口都改用它：`ClientPort`/`RPCPort`（连续 5 个）、EasyTier 的 `ListenersPort`（连续 3 个）、直连 `DirectListenPort`。
  - 自愈重试：直连房主启动后用 `WaitPortListening(DirectListenPort, 3000)` 确认端口真的在监听，没起来就换 `PickBindablePorts(1, 11010, 旧端口)`，替换参数里的 `--listeners tcp://... udp://...`、重新做 UPnP 映射、`ProcessStop()` 后重启，最多 2 次；仍失败才 `Panic`，文案直接点明「Hyper-V / WSL / Docker 会预留端口段」并附最近日志。
- **验证**（`F:\PCL2-PortTest`）：建房间日志 `直连模式监听端口：21277`（落在 20000–30000 区间）、`UPnP 映射成功：192.168.2.12:21277`、`加载器 联机 状态改变：Finished`；`Get-NetTCPConnection -LocalPort 21277` 与 `Get-NetUDPEndpoint` 都是 Listen/Bound，`联机模块` 进程存活，无崩溃。
- **坑**：`#Region` 块被新增代码切开后，`#End Region` 数量会不匹配（`BC30681`）；首次启动会被 Windows 防火墙拦一次「PCL Harness 启动器」的网络访问，点「允许」后端口才真正可绑。
- **版本**：3.4.6 / 428，changelog 一条（修复陌生环境端口被预留导致的崩溃）。

## §21.30.19 直连邀请带上外网地址（3.4.7）

- **用户反馈**：让另一台电脑（不同网络）的朋友加入房间，启动器弹「无法连接到节点」，日志里 EasyTier 在反复连 `udp://192.168.1.109:24828` / `tcp://192.168.1.109:24828`。
- **根因**：直连邀请只写了房主的**局域网**地址（`GetDirectInvite` 里 `LanIp:DirectListenPort|邀请码`）。同一局域网能用，跨网络时这个地址根本不可达；房主侧的 UPnP 外网映射其实成功了，但外网地址只显示在完成页的「外网地址」一行，没有进邀请串，朋友拿到的仍然是一条连不上的内网地址。
- **修复**（`Pages\PageLink\PageLinkMain.xaml.vb`）：
  - `GetDirectInvite()` 改为地址列表：UPnP 映射成功时把外网地址排在前面，局域网地址附在后面，用逗号分隔（`222.69.206.227:24569,192.168.2.12:24569|邀请码`），去重后拼接。
  - 加入侧 `JoinInternal` 解析 `|` 左侧时按逗号拆成多个地址（`DirectPeerAddresses`），每个地址分别生成 `tcp://` 与 `udp://` 两条 `-p`，EasyTier 会依次尝试，外网在前；旧格式（单个地址）照旧可用。
  - 完成页文案同步：外网已映射时提示「已经带上外网地址，外网的朋友也能直接加入（前一个优先，后一个给同一局域网用）」；没映射时明确写「这条邀请只能在同一局域网里用」。
  - 加入失败的错误框升级：若邀请里全是内网地址（`IsPrivateEndpoint` 判断 10/8、172.16/12、192.168/16、127/8、169.254/16），直接说明「这条邀请只有内网地址，只能和房主在同一局域网使用」，并告诉房主该开 UPnP 或手动端口映射后重建房间。
- **验证**（`F:\PCL2-InviteTest`）：建房间日志 `直连模式监听端口：24569` + `UPnP 映射成功`，自动复制的邀请为 `在 PCL 启动器中输入邀请【222.69.206.227:24569,192.168.2.12:24569|P63DD-RUYHZ-V99ZB-02000】，即可加入联机房间！`——外网地址在前、局域网在后，加入侧按逗号解析后两个地址都会进 `-p`。
- **后续**：真正的双机跨网络联机仍需两台电脑实测（本机只有一台，且两台实例会被单例互斥体挡住）。
- **版本**：3.4.7 / 429，changelog 两条（修复邀请缺外网地址、优化跨网络失败提示）。

## §21.30.20 联机诊断能测出真实 NAT 类型（3.4.8）

- **用户反馈**：「每一次开房间并生成联机诊断时都检测不到 NAT 类型」——诊断里「自己的 NAT 类型」永远是「未知（没有 STUN，或对端没报）」。
- **根因**：NATType 取自 EasyTier CLI 自己那条 peer 记录的 
at_type，而直连模式为了让房间不依赖任何公共服务，启动参数里写的是 `--p2p-only true --stun-servers ""`，EasyTier 因此完全不做 STUN，
at_type 恒为 Unknown。
- **修复**（`Pages\PageLink\PageLinkMain.xaml.vb`）：
  - 新增 `TryStunQuery(Server)`：手写一个 STUN Binding Request（20 字节，type 0x0001、magic cookie `21 12 A4 42`、12 字节事务号），解析 `XOR-MAPPED-ADDRESS`（0x0020，端口与 `0x2112` 异或、IPv4 与 cookie 异或）和 `MAPPED-ADDRESS`（0x0001），超时 1.2 秒，失败静默返回 Nothing。
  - 新增 `ProbeNatByStun()`：依次问 `stun.miwifi.com`、`stun.hitv.com`、`stun.cloudflare.com`、`stun.l.google.com`，凑够两份映射就停；两份端口相同判为锥形 NAT（能打洞），不同判为对称型 NAT（打洞容易失败，建议房主做端口映射），一份或零份也各有明确文案。
  - 新增 `NatProbeResult` / `NatProbeStarted` / `EnsureNatProbe()` / `GetSelfNatDescription(WaitProbe)`：状态条悬停提示在后台补探测（不阻塞 UI），诊断报告在后台线程直接探测完再输出；`InitLaunch` 每次开房间重置缓存，换网络后不会沿用旧结果。
- **坑**：第一版把「Binding Success Response」判成 `Response(0) = 0`，而实际 STUN 成功响应类型是 `0x0101`（首字节为 $），导致所有服务器都被当成无响应；改成 `Response(0) = 1 AndAlso Response(1) = 1` 后立刻拿到映射。
- **验证**（`F:\PCL2-NatTest`，直连房主 25565）：诊断输出 `自己的 NAT 类型：对称型 NAT（两个服务器看到不同映射 61.171.218.65:7202 / 61.171.218.65:7391，打洞容易失败，建议由房主做端口映射）`，日志同时记录 `[PageLinkMain] NAT 探测结果：…`；版本行 `3.4.8（VersionCode 430）`。
- **副作用**：这是唯一会主动联系第三方服务器的行为（STUN，仅用于判断 NAT 类型，不涉及房间流量），四个服务器都是公共 STUN，不写日志之外的任何上报。
- **版本**：3.4.8 / 430，changelog 两条（修复 NAT 检测、优化每次开房间重测）。
## §21.30.21 TUN 模式自动提权（3.4.9）

- **用户反馈**：「TUN 模式开启时并没有进行自动提权，只有前面的安装虚拟网卡成功弹出 UAC 了」——即只把联机模块提权，启动器自己仍是普通权限，界面上看起来像「半吊子提权」。
- **根因**：此前只在 `ProcessStart` 里判断 `If IsTunMode AndAlso Not IsAdmin()`，用 `cmd /c link-elevated.cmd`（`Verb=runas`）单独拉起联机模块；启动器本身从不提权，因此「任务管理器里启动器还是普通权限」「诊断里权限一直显示普通用户」。
- **修复**（`Pages\PageLink\PageLinkMain.xaml.vb`）：
  - 新增 `EnsureAdminForTun()`：TUN 且非管理员时先 `Hint("TUN 模式需要管理员权限，正在以管理员身份重启启动器……")`，再以管理员身份重启；UAC 被拒绝时给「需要管理员权限」的明确提示而不是继续往下走。
  - 调用点放在真正开始建房/加入之前：`Create_MouseLeftButtonUp`（拿到端口后）和 `JoinInternal`（校验邀请码后），返回 False 就直接结束本次操作。
  - 提权重启用「延迟拉起」：`cmd.exe /c ping -n 4 127.0.0.1 >nul & start "" "<exe>"`（`UseShellExecute=True`、`Verb=runas`、`WindowStyle=Hidden`），旧实例在 400 ms 后关闭，等单实例互斥体释放后提权 cmd 再把启动器拉起来。
  - 联机模块因此直接继承启动器的管理员令牌，`ProcessStart` 里不再对模块单独提权，只记一行 `TUN 模式：当前启动器已有管理员权限，联机模块直接继承，不会再弹 UAC`。
- **坑**：第一版是「先 `Process.Start(runas)` 再关自己」，结果新实例抢在旧实例退出前启动，被单实例机制判为「已有实例」，旧实例收到关闭指令退出、新实例也自行退出，最后一个启动器都不剩（旧实例日志可见 `收到置顶信息` / `窗口已置顶` / `收到关闭指令`）。改成延迟拉起后正常。
- **验证**（`F:\PCL2-TunTest`，`LinkTunMode:True`）：点「创建房间」只弹一次 UAC，同意后旧实例退出、新实例日志首行 `管理员权限：True`、版本 `3.4.9 (431)`；随后建房日志 `虚拟网卡已就绪：10.114.114.1`、`联机 状态改变：Finished`，`Get-NetIPAddress` 出现 `10.114.114.1`（接口 `et_5_*`），全程没有第二次 `consent.exe`。
- **联机诊断**：权限行改为 `启动器权限：管理员` / `普通用户（TUN 模式会自动以管理员身份重启启动器）`，避免用户误判。
- **版本**：3.4.9 / 431，changelog 两条（修复 + 优化）。

## §21.30.25 登录页精简与旧版登录信息导入（3.4.13）

**需求**：主页正版账号未登录时不要那一长串说明（步骤在登录弹窗里已有）；并尝试像其它设置一样，首次启动时把旧 PCL2 的正版登录凭据迁移过来。

**改动**
- `Pages\PageLaunch\PageLoginMs.xaml.vb`：配置了 Client ID 时把 `LabMsNotWired` 清空并 `Collapsed`，登录页只保留头像、账号下拉、登录按钮与「购买正版 / 前往官网」两个链接；未配置 Client ID 的红字提示保留。
- `Modules\ModFirstRun.vb` 新增 `TryImportLegacyLogin()`（`Application.xaml.vb` 里紧跟 `AutoMigrateOnStartup()` 调用）：本程序登录信息为空时，从 `HKCU\Software\PCLDebug` 导入 `LoginMsJson`、`CacheMsV2*`、`LoginType`、`LoginRemember` 等 10 项原始注册表值，成功后日志「已从旧版 PCL（开源构建）导入正版登录信息：N 项」；用 `LoginImportDone` 标记保证只做一次。
- 若本程序未登录、而 `HKCU\Software\PCL`（官方 PCL）里有 `LoginMsJson`，日志写「检测到官方 PCL 的登录信息，但它使用官方内置的机器码加密，本程序无法解密；需要在 PCL Harness 中重新登录一次」。

**为什么官方 PCL 的登录凭据迁移不了（实测结论）**
- PCL 的设置项加密为 DES：`key = StableHash("PCL" + Identify)` 取 8 字符，IV 固定 `95168702`；`Identify` 在开源构建里是占位符 `"0000-0000-0000-0000"`，官方构建用的是内置机器码（开源仓库里同样是占位符，真实算法未公开）。
- 实测：把 `HKCU\Software\PCL` 的 `LoginMsJson` / `CacheMsV2Access` / `CacheMsV2OAuthRefresh` 原样写进 `HKCU\Software\PCLHarness` 后启动，日志报 `解密设置失败：LoginMsJson：不正确的数据`，随后被重置为默认值 —— 即两套 Key 不同，密文不可复用。
- 结论：官方 PCL → PCL Harness 只能重新登录一次（登录后本程序会一直记住）；从**开源构建（PCLDebug）**迁移则可以直接复用凭据（同一套 Key）。

**版本**：3.4.13 / 435，changelog 两条。
