## 4. 更新检查（确认无官方源）

`Modules\ModSecret.vb` 的 `UpdateCheckByButton` 只读 `PCL_UPDATE_JSON_URL`：

- 未设置 → 只弹提示，不发任何请求；
- 设置为 http(s) → `HttpClient` 取 JSON（10s 超时）；
- 设置为本地路径 → 直接读文件；
- 版本比较用 `CompareVersion(latest, VersionBaseName)`（`ModMinecraft.vb:2431`）。

上游开源版本来就没有官方更新接口（`ModSecret.vb` 里是 `Hint("该版本中不包含更新功能……")` 的占位），因此这里不需要「删除官方源」，只需保证默认不联网——已满足。

> 注意：版本号升到 3.0.0 后，若更新 JSON 里仍是 `2.99.0.0`，不会提示更新（3.0.0 更新）。测试时把 `latest` 写到 `9.9.9.9` 之类。

## 12. 插件页改用原生左侧栏 + 扩展点改展开卡片

**为什么改**：第一版把左侧栏做在页面内部（`MyPageRight.Child` 里的 Grid），靠 `Visibility` 切换分区。结果：`MyCard` 在 `Collapsed` 状态下被加载时，`Init()` 里的虚拟化与高度动画按 0 尺寸算过一次，重新显示后卡片会变灰、内容消失。改成重建式切换后问题消失。

**左侧栏**
- 新增 `Pages\PagePluginLeft.xaml(.vb)`：`Inherits` 原生 `MyPageLeft`，`AnimatedControl="PanItem"`，三项 `MyListItem`（`Type="RadioBox"`、`Height="36"`、`MinPaddingRight="35"`），与 `PageSetupLeft` 完全同构，挂在主窗口 `PanMainLeft` 上。
- `ModMain.vb:400` 新增 `Public FrmPluginLeft As PagePluginLeft`；`FormMain.xaml.vb:1600` 的 `Case PageType.Plugin` 由 `PageChangeAnim(New MyPageLeft, FrmPlugin)` 改为 `PageChangeAnim(FrmPluginLeft, FrmPlugin)`。
- `PagePluginLeft.PageCheck` 直接调 `FrmPlugin.SwitchSection(Tag)`。

**右侧页面**
- `PagePlugin.xaml` 只剩一个宿主：`MyPageRight(PanScroll="PanBack")` → `MyScrollViewer(PanBack)` → `StackPanel(PanContent, Margin 25,25,25,10)`。
- `SwitchSection(Index)`：`PanContent.Children.Clear()` 后按分区重建（管理 / 扩展点 / 开发说明），带 `IsRebuilding` 重入锁，`ScrollToVerticalOffset(0)`。
- 卡片内容必须 `Card.Children.Add(Body)` 且 `Body.Margin = (25,40,25,20)`；用 `BorderChild` 会把内容塞进背景 Border（无内边距、与标题重叠）。

**扩展点改为每插件一张可展开卡片**
- `NewCard($"{DisplayName}  v{Version}")` + `CanSwap = True`、`SwapControl = Body`、`IsSwapped = False`（False 才是展开，MyCard 语义如此），点标题或右上箭头折叠。
- 卡内：一行统计（页面 N · 标题栏入口 M · 设置项 K）+ 每个页面/入口/设置项一行，右侧控件为「打开页面」按钮 / 复选框 / 输入框+保存。

**顺带修掉的重复注册 bug**
- `ModPlugin.SetEnabled` 重新启用插件时，`LoadOne → CollectUi` 会把页面、入口、设置项再追加一遍，标题栏出现两个「示例」。在 `CollectUi` 开头调新增的 `RemoveUi(Info)`（`PluginPages/PluginNavItems/PluginSettings` 各自 `RemoveAll`）修正。

**验证**：三区切换正常、扩展点卡片折叠/展开正常、启用→禁用→启用无重复入口、插件自定义页面仍可从标题栏打开。截图 `screenshots/28-插件页-左侧栏原生.png`、`29-扩展点-每插件展开卡片.png`、`30-扩展点-折叠态.png`、`31-插件开发说明.png`。

  - 文件不存在 / 解析失败 / 缺 `Link` 节点时，抛出的错误信息会直接给出应当放置的完整路径。

- 示例配置：`samples\LinkConfig\ServerConfig.example.json`，`Link` 节点包含 `EasyTierVersion / Downloads / Argument / Peers / MandatoryPeers / PeersBlackList / RandomPeer / DiscoverPeerId / DiscoverPeer`。
  - `Downloads` 支持 `{arch}` 占位（x86_64 / aarch64）；`EasyTierVersion` 用于判断是否需要重新下载。
  - 复制的目标位置：`%AppData%\PCL\ServerConfig.json`（也可以直接放到 exe 同级的 `PCL\ServerConfig.json`，程序会优先用 AppData 那份）。

**EasyTier 模块**
- 官方下载的 zip 里就是 `easytier-core.exe` / `easytier-cli.exe` / `Packet.dll` / `wintun.dll` / `WinDivert64.sys`。解压到 `%AppData%\PCL\EasyTier\` 后重命名为 `联机模块.exe` / `联机模块 CLI.exe` 即可被识别。
- 版本检查读的是注册表 `HKCU\Software\PCLDebug` 的 `LinkEasyTierVersion`（`Sources.Registry`），与 `Setup.ini` 无关；要跳过下载就把该值写成配置里的 `EasyTierVersion`。
- 开源版原解压代码调用的 `FileUtils.ExtractToDirectory` 与 `DirectoryUtils.Copy/EnumerateDirectories` 都被裁掉了（整段只剩注释），已改用 `IO.Compression.ZipFile.ExtractToDirectory` + 手写遍历复制；`System.IO.Compression.FileSystem` 引用本来就在 vbproj 里。

**CLI 调用（关键）**
- `RefreshPeer` 里原本是 `Dim CliResult = ""`，真正的 `StartProcessAndGetOutput(...)` 被注释掉——也就是说即使模块起来了，也永远拿不到节点列表。
- 开源版没有 `StartProcessAndGetOutput`，新增 `RunCliAndGetOutput(FileName, Arguments, TimeoutMilliseconds)`：`ProcessStartInfo` + 异步读取 stdout/stderr + `WaitForExit(timeout)`，超时则 `Kill()` 并抛出明确异常。
- 现在每次刷新都会真正执行 `联机模块 CLI.exe -o json -p 127.0.0.1:{RPCPort} peer`，返回的 JSON 里 `lat_ms` 字段用于判断连接是否建立。

**实测结果（本机）**
- 配置读取：通过，日志 `已从本地加载联机配置`。
- 模块启动：通过，`联机模块.exe` 按 PCL 生成的参数启动，`new listener added listener=tcp://0.0.0.0:12427` 等日志正常。
- CLI 解析：通过，`EasyTier CLI` 加载器以约 60ms 完成，没有出现 `CLI 调用失败`。
- 卡点：公共节点 `public.easytier.cn` 在本机 DNS 返回 NXDomain（`easytier.cn` 可解析但 11010 端口不可达），房间停在「正在连接到节点……」，约 40 秒后失败退出。

**结论**：PCL 侧的联机链路（入口 → 配置 → 下载/解压 → 启动 → CLI 解析）已经全部打通，剩下的只是「能连上的节点」这一外部条件。把可达的中继写进 `ServerConfig.json` 的 `Peers`（或在设置 → 联机 → 自定义节点里填）即可继续。

## 16. 正版登录与 CurseForge：凭据从哪来、怎么配

两个问题都**不是代码缺失**，而是开源版把两把「钥匙」删掉了。登录的 6 步流程、CF 的搜索/文件接口在代码里都是完整的，只是没有 Client ID / API Key。

### 16.1 凭据统一放在 PCL\Secrets.json

支持两种注入方式，环境变量优先：

1. 环境变量：`PCL_MS_CLIENT_ID`、`PCL_CURSEFORGE_API_KEY`
2. 文件 `PCL\Secrets.json`（exe 同级的 PCL 目录下，和 `Setup.ini` 放一起）：
   ```json
   { "MsClientId": "你的客户端 ID", "CurseForgeApiKey": "你的 API Key" }
   ```
   模板：`samples\Secrets.example.json`。改完**重启** PCL Harness 生效。

实现：`Modules\ModSecret.vb` 的 `SecretValue(JsonKey, EnvironmentKey)`，惰性读取并缓存，解析失败只写一条警告，不影响启动。

### 16.2 正版登录（微软账号）

> **前提（2026-10 核对官方文档）**：个人微软账号（@outlook.com / @hotmail.com / @live.com）**不能**直接登录 <https://entra.microsoft.com> 注册应用。这类账号默认被路由到 "Microsoft Services" 租户、其中没有可管理的目录，打开后报 `AADSTS50020` / `AADSTS50058`。
>
> 官方两条硬限制：注册应用所在租户的前提是「An Azure account that has an active subscription」；且「Only paid customers can create a new Workforce tenant…Customers using a free tenant, or a trial subscription won't be able to create additional tenants from the Microsoft Entra admin center」。所以**必须先注册 Azure 账号**——注册流程会自动创建租户，注册者成为该租户的全局管理员，之后才能在 Entra 里注册应用。

步骤（Azure 免费账号 → 注册应用）：

0. 用 InPrivate 窗口打开 <https://azure.microsoft.com/pricing/purchase-options/azure-account> → 「免费开始使用」，用个人微软账号注册 Azure（需手机验证 + 信用卡预授权，试用额度内不扣费）。注册完成后账号下会自动出现一个 Entra 租户，右上角能看到租户名。

1. 打开 <https://entra.microsoft.com> → 「应用」→「应用注册」→「新注册」。
2. 名称随便（如 `PCL Harness Login`）。
3. 「受支持的账户类型」选 **仅此组织目录中的账户** 或 **任何组织目录中的账户和个人 Microsoft 账户** 都可以，但要让个人号能登就必须包含「个人 Microsoft 账户」。
4. 重定向 URI 留空即可（设备代码流不需要）。
5. 注册完成后记下「应用程序(客户端) ID」。
6. 进「身份验证」→ 拉到底部「高级设置」→「允许公共客户端流」选 **是**（`Enable the following mobile and desktop flows` / `Allow public client flows`）。**这一步不做，设备代码流会直接失败。**
7. 不需要生成客户端密码。

然后把客户端 ID 填进 `Secrets.json` 的 `MsClientId`（或环境变量 `PCL_MS_CLIENT_ID`），重启 → 启动页「正版」→「登录」，会出现设备代码弹窗（一串代码 + 一个网址），浏览器打开输入即可。

- 未配置时的表现：会直接弹红字提示「尚未配置微软登录的客户端 ID…」，而不是抛微软返回的 400 原始 JSON（`EnsureOAuthClientId()`，在 `MsLoginStep1New` / `MsLoginStep1Refresh` 开头调用）。
- 刷新登录走 `login.live.com/oauth20_token.srf`，与首次登录的 v2.0 设备代码端点共用同一个 Client ID，这是原版行为，保持不变。

### 16.5 没有信用卡 / 没有学校账号时，正版登录还有哪些路

**结论先说：没有「用个人微软账号 + 不绑卡」就能自建租户的官方路径。** 租户是注册应用的前提，而租户的前提是 Azure 账号（活跃订阅），Azure 免费账号的注册又要手机 + 信用卡预授权。所以下面几条是替代，不是绕开：

| 路径 | 要不要卡 | 能做什么 | 代价 / 限制 |
| --- | --- | --- | --- |
| **A. 加入别人的租户（guest）** | 不要 | 在对方租户里注册自己的应用，拿到 Client ID，正版登录完整可用 | 需要认识一个有租户的人（Azure / M365 都行）；对方要给你 `Application Developer` 角色，或在「用户设置」里允许用户注册应用；离开租户即失效 |
| **B. 外置登录（LittleSkin / Authlib-Injector）** | 不要 | 用皮肤站账号登录，进支持外置登录的服务器；皮肤、披风正常 | 不是 Mojang 正版身份，进不了只认正版服的服务器；**必须先装一个游戏版本才有入口**（见下） |
| **C. 离线登录** | 不要 | 单机、局域网、离线服 | 无正版身份，部分服务器拒绝 |
| **D. 借用公开 Client ID（灰色）** | 不要 | 技术上能跑通设备代码流 | **不推荐**：违反 Microsoft 使用条款，随时被吊销；令牌经过别人的应用，账号安全不受控。仓库不内置、不提供任何具体 ID |

**已验证的事实（2026-10，本机实测）**
- LittleSkin 的 Yggdrasil 端点 `https://littleskin.cn/api/yggdrasil` 返回 200，`meta.serverName = LittleSkin`，`implementationName = Yggdrasil Connect 0.0.8`，`signaturePublickey` 800 字符 —— 协议层可用。
- `authlib-injector` 最新版 **1.2.8**，主源 `https://authlib-injector.yushi.moe/artifact/latest.json` 与 BMCLAPI 镜像 `https://bmclapi2.bangbang93.com/mirrors/authlib-injector/artifact/latest.json` 都返回 200，PCL 里两条都会走（`ModMinecraft.vb:2105` 起，含镜像替换）。

**外置登录在 PCL 里的入口（为什么很多人找不到）**
- 登录类型是 `McLoginType.Auth`（`PageLaunchLeft.xaml.vb:357-362`），标签取 `CacheAuthServerName` / 版本级 `VersionServerAuthName`，为空时显示「第三方登录」。
- 它绑定在**版本**上：没选版本时点它只会提示「请先下载游戏，再设置第三方登录！」（`FormMain.xaml.vb:1005`）。所以顺序是 **先装游戏 → 再配置 authlib 服务器**。
- 两种配置方式：① 在「版本设置 → 设置 → 服务器选项」里填 authlib 服务器地址（PCL 自带「覆盖为 LittleSkin 登录」按钮，`PageInstanceSetup.xaml.vb:378`）；② 点 `authlib-injector:yggdrasil-server:<url>` 协议链接，PCL 会自动接管（`FormMain.xaml.vb:967-1022`）。
- 启动时会把 `authlib-injector.jar` 作为 `-javaagent` 注入，并传 `-Dauthlibinjector.yggdrasil.prefetched=<base64(服务器元数据)>`（`ModLaunch.vb:1287-1291`）。

**不建议**：用虚拟信用卡凑 Azure 验证去过免费额度。涉及资金与合规风险，而且订阅到期/被风控会连累租户。

**如果以后拿到 Client ID**：直接填 `PCL\Secrets.json` 的 `MsClientId`（或环境变量 `PCL_MS_CLIENT_ID`）即可，代码侧不需要再改。

## 17. 示例插件瘦身 + 插件页分区切换动效

**示例插件默认不再注册页面和标题栏入口**（`samples\DemoPlugin\DemoPlugin.vb`）
- 顶部新增条件编译开关 `#Const DemoPageEnabled = False`：`GetPages` / `GetNavItems` 在关闭时返回空集合，`GetSettings` 只保留「加载时弹出提示」。想恢复整套演示，把 `False` 改成 `True` 重新编译即可。

**插件页左栏切换加回入场动效**

## 17. 插件 API v3：事件钩子、更多设置类型、宿主增强

**为什么要做**：v2 只能注册「页面 / 入口 / 设置项」，插件拿到控制权只有 `OnLoad` 一次；想在页面切换、游戏启动前后做点事就没办法。

**`IPclPluginEvents`（新接口，可选实现）**
- `OnLauncherReady()`：启动器初始化完成、所有插件加载后调一次（`FormMain` 初始化线程末尾 `RunInUi` 里 `ModPlugin.RaiseLauncherReady()`）。
- `OnPageChanged(Page, SubType)`：主页面切换后触发（`FormMain.PageChange` 与 `PageChangeActual` 两处调用 `RaisePageChanged`）。
- `OnGameLaunching(Info)`：构建启动参数时触发，可向 `Info.ExtraJvmArgs` / `Info.ExtraGameArgs` 追加参数（`ModLaunch.McLaunchArgumentMain` 内追加，`InstanceName` / `InstanceFolder` / `PlayerName` 一并带上）。
- `OnGameLaunched(Info)`：进程启动后触发，`Info.ProcessId` 可用（`McLaunchRun` 里拿到的 PID 回填）。
- 所有回调都包在 try/catch 里，插件异常只记日志，不打断启动器；`PluginEventHandlers` 列表由 `CollectUi` 收集，`RemoveUi` 一并移除，避免重载重复触发。

**设置类型扩展**
- `PluginSettingType` 增加 `Number`（`MinValue` / `MaxValue`，越界夹紧）与 `Choice`（`Options As String()`）。
- 插件页的 `BuildSettingControl` 相应渲染为「输入框 + 范围提示 + 保存」与「`MyComboBox` 下拉，选中即写入」。
- 写入仍走 `ModPlugin.SetSetting`，落 `PCL\Plugins\plugins.settings.json`。

**`PluginHost` 增强**
- 新增 `InstanceName` / `InstanceFolder` / `PlayerName`（当前选中的版本与玩家）。
- 新增 `Navigate(Page As Integer)`（切主页面，参数为 `FormMain.PageType` 数值）。
- 新增 `RunInUi(Action)` 与 `RunLater(Milliseconds, Action)`，省得插件自己写 Dispatcher。

**示例插件同步升级到 v1.3.0**：实现 `IPclPluginEvents`（就绪时打日志、页面切换时记一行、启动前后各记一行），设置项变成三类共 3 个（勾选 / 数字 1~5 / 下拉主题），可直接当模板抄。

**文档**：`PLUGIN-DEV.md` 标题升到 API v3，文末追加「API v3 追加内容」（事件接口、设置类型表、`Host` 成员表、版本对照）。

## 20. 联机直连模式（P2P-only）

### 20.1 需求与结论

用户希望联机"只利用 P2P 直连，直接本地化"。结论：**可行，但只在特定网络条件下成立**。

- 可行：同局域网直连；房主公网可达（有公网 IP / 已做端口映射 / 路由器支持 UPnP）。
- 不可行：任意 NAT 后两端零服务器互通。NAT 穿透必须有第三方交换地址（STUN、发现节点、信令服务器皆属此类），这是协议层限制，无法靠改代码消除。
- 另一个与服务器无关的硬依赖：EasyTier 需要 TUN 虚拟网卡（管理员权限 + wintun 驱动）。本机实测未装驱动时 `-i` 直接报 `Failed to create adapter`；`--no-tun` 时无可用本地地址，连接报 `10049 AddrNotAvailable`（smoltcp 亦未成功）。

### 20.2 实现内容

- 新增 `Modules\ModUpnp.vb`：极简 UPnP IGD 客户端（SSDP 发现 → 取设备描述 → `AddPortMapping` TCP/UDP → `GetExternalIPAddress`）。本机路由器（Huawei-ATP-IGD，192.168.2.1）可被 SSDP 发现。
- `Pages\PageSetup\PageSetupLink.xaml` 新增「直连模式」卡片与 `LinkDirectMode` 开关。
- `Pages\PageLink\PageLinkMain.xaml.vb`：
  - `IsDirectMode`、`DirectPeerAddress`、`DirectListenPort`、`DirectPublicEndpoint` 四个状态；
  - 直连模式下完全跳过 `GetTargetPeers()`（不再访问 `uptime.easytier.cn`、`easytier.meloong.com`、发现节点与中继）；
  - 启动参数追加 `--listeners tcp://0.0.0.0:{DirectListenPort} udp://0.0.0.0:{DirectListenPort}`、`--p2p-only true`、`--stun-servers ""`（禁用内置 STUN）；
  - 房主启动后尝试 UPnP 映射该端口，成功则邀请里附带外网地址；
  - 邀请格式变为 `房主IP:端口|邀请码`，`JoinInternal` 会先剥离【】再按 `|` 拆出地址与邀请码；
  - 直连房主不再等任何节点，启动 1.2s 后直接进入完成页；
  - `ProcessStart` 增加管理员检查，无权限时用 `Verb = "runas"` 提权启动联机模块（此时无法重定向输出，不影响功能）。
- `ModUpnp.vb` 需加入 `.vbproj` 的 `<Compile Include>`，否则报 `BC30451 未声明 ModUpnp`。

### 20.3 使用方法与限制

1. 设置 → 联机 → 勾选「只使用 P2P 直连」。
2. 房主：联机 → 创建房间 → 输入 MC 对局域网开放的端口；页面显示 `IP:端口|邀请码`，并自动复制。
3. 加入者：联机 → 加入 → 粘贴整串。
4. 首次启动联机模块会弹 UAC（创建虚拟网卡需要管理员），选「是」。

限制：同一局域网最稳；公网需要 UPnP 或手动端口映射；若双方都在对称 NAT 后且路由器无 UPnP，则仍然连不上——这种情况必须有中继或公网端点，这是无法绕过的。

### 22 联机直连「建房 1 秒后网络连接已断开」的修复

### 21.16 首次启动指引窗口：按钮点了没反应（v3.1.6）
用户反馈（m09255）：首次启动界面里的「跳过」点了没反应。

- 现象与定位：`FirstRunWindow` 是 `WindowStyle.None` + `AllowsTransparency` 的无边框窗口，构造函数里给整个 Window 挂了 `MouseLeftButtonDown → DragMove()` 用于拖动窗口。于是**按在按钮上的首次 MouseDown 也被 Window 的处理器接走并进入拖拽（鼠标被捕获）**，按钮收不到 MouseUp，`Click` 永远不触发——窗口本身看着正常，按钮却全部失效。
- 修复（`Plain Craft Launcher 2/Modules/ModFirstRun.vb`）：
  - 新增 `Private Function IsInteractiveSource(Source As Object) As Boolean`，沿 `VisualTreeHelper.GetParent` 向上找 `MyButton`/`MyCheckBox`/`MyTextBox`/`MyComboBox`。
  - `MouseLeftButtonDown` 处理器首行加 `If IsInteractiveSource(e.OriginalSource) Then Return`，只有点在文字/空白处才 `DragMove()`；滚动容器不算交互控件（内容区仍可拖）。
- 验证：重建部署后删除 `FirstRun.done` 重启，用真实鼠标事件点击「跳过」→ 日志 `[首次启动] 点击跳过`，`FirstRun.done` 写出，窗口关闭；「打开旧目录」「迁移并进入」同一处理器一起恢复。
- 顺带教训：自动化脚本必须 `SetProcessDpiAwarenessContext(-4)` 后再 `SetCursorPos`/`mouse_event`，否则 125% 缩放下坐标被虚拟化，点击会落到别的窗口。
