# brief-template

> 执行者 → 顾问。≤ 800 字。只贴关键片段，不整文件粘贴。

## 目标

一句话：这一轮要决定的到底是什么。

## 现状与证据

- 相关文件与行号（例如 `ModPlugin.vb:4819` 的轮询循环）。
- 关键日志/命令输出（3–8 行，原文）。
- 已经排除的可能（谁在什么时候用什么证据排除的）。

## 约束

- 不能动的：编码契约（UTF-8 无 BOM + LF）、权限模型、已发布的 API 语义。
- 代价敏感项：一次发版的成本、插件作者要跟着改的地方。
- 已知坏路径：例如「把可见性切换塞进 FitPluginNav 事务会让折叠整体跳过」。

## 候选方案

1. 方案 A —— 一句话描述 + 代价 + 风险。
2. 方案 B —— 同上。
3. 方案 C（若需要）——同上。

## 想要的回答

按四段回：**推荐 / 理由 / 风险 / 如何证伪**。
如果三个方案都不行，直接说「都不行」并给第四种。
